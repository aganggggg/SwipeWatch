# 上滑助手 SwipeWatch

一个不需要 root 的 Android 小工具：**盯住屏幕，一出现「上滑继续观看」之类的提示，就自动帮你向上滑一屏。**

不联网。节点能读到文字时不截屏，只在读不到的页面上才截屏幕底部一条做本地识别。

---

## 一、原理

要在别的 App 上「看见字」并「动手滑」，非 root 只有一条通道——无障碍服务。它顺便把三件事都包了：

| 能力 | 系统 API | 额外授权 |
| --- | --- | --- |
| 读界面文字 | `getWindows()` + `findAccessibilityNodeInfosByText()` | 无 |
| 截图（兜底） | `takeScreenshot()`（API 30+） | 无，同上 |
| 在别的 App 上滑 | `dispatchGesture()`（API 24+） | 无，同上 |

所以**全程只有一次授权**：无障碍设置里手动开一次。没有录屏确认弹窗，没有前台服务，没有通知栏常驻。

链路：

```
每 400ms 遍历所有窗口，查关键词          1~5ms
  ├─ 查到 → dispatchGesture 上滑
  └─ 查不到 → 每 1.5s 截一帧，先看顶部是不是黑的
                ├─ 不是黑（正常全屏视频）→ 跳过，什么都不做
                └─ 是黑（广告/画中画）→ 只识别底部一条   截图 ~40ms + 识别 ~200ms
```

### 为什么需要「截图兜底」

红果的提示有三种形态，节点方案只能覆盖前两种：

| 形态 | 提示在哪 | 能不能读到 |
| --- | --- | --- |
| 正常剧集结束 | 原生 `TextView`：「上滑继续观看短剧」 | 能，1~3ms |
| 普通广告 | 原生 `TextView`：「3秒后可继续上滑观看短剧」 | 能，但**文案会倒计时、语序还反着** |
| 小程序广告 | 画在视频画面里（整页自绘，节点树里是空的） | **不能，只能看图** |

第三种是最早漏掉的那类：屏幕上下全是黑边、中间一条 16:9 的小游戏广告，底部「上滑继续观看短剧」是画面的一部分，43 个无障碍节点里一个字都没有。

### 两个容易踩的坑

**坑一：`rootInActiveWindow` 会拿到下面那一层。** 广告盖在播放页上面时，活动窗口返回的其实是底下的播放页节点（能读到「第44集」「发弹幕」），广告内容完全不在里面。所以必须 `getWindows()` 遍历所有窗口，再逐个查。

**坑二：节点里那些字可能是看不见的。** ViewPager / RecyclerView 会把相邻页面缓存在树里，那些节点带文字但用户看不见。判断「这页有没有字」必须过滤 `isVisibleToUser`。

## 二、匹配规则

关键词默认「上滑继续观看」，写前缀就够了。匹配不是简单的 `contains`：

1. **滑动窗口 + LCS**：容忍 OCR 错一两个字（滑→猾、继→断）。
2. **不看顺序的字符重叠率**：容忍语序差异。红果有个广告位写的是「3秒后可**继续上滑**观看短剧」，字符和「上滑继续」完全一样只是换了位置，只算 LCS 只能拿到 50%，会被判成不匹配。两种比法取大的那个。

多个关键词用逗号分隔，界面里可以改。

---

## 三、防重复触发

滑过一次之后，必须**先观察到提示消失**（连续 2 轮扫不到），才允许下一次触发。

否则会这样：广告页的提示一直挂着、滑了也没用，静默时间一到又滑一次，每 10 秒循环一遍。日志里会写明没滑的原因：`已滑过，等提示消失` / `冷却中 3.0s`。

---

## 四、可调参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 检测频率 | 400 ms | 节点轮询间隔。读一次只要 1~3ms，可以设密 |
| 兜底识别间隔 | 1500 ms | 只在「查不到关键词」时才截图，正常页面不触发 |
| 兜底截图范围 | 屏幕底部 12% | 红果的提示在底部 5% 左右，12% 留了余量 |
| 文字匹配阈值 | 70% | 调高更严格，调低更容易命中 |
| 触发后静默 | 2.5 s | 上滑后这段时间完全停止检测，可调 1 秒 ~ 5 分钟（对数刻度） |
| 滑动时长 | 350 ms | 手势快慢 |
| 滑动距离 | 屏高 55% | 一次滑动跨过多少屏幕 |
| 触发关键词 | 上滑继续观看 | 逗号分隔，写前缀即可 |

## 五、工程结构

```
app/src/main/java/com/swipewatch/app/
├── MainActivity.kt              Compose 设置界面
├── SwipeAccessibilityService.kt 读节点 + 截图 + 执行手势 + 轮询循环
├── StripOcr.kt                  兜底截图：takeScreenshot → 裁底部 → ML Kit 离线识别
├── Detector.kt                  匹配 + 边沿触发 + 静默 + 记账
├── TextMatcher.kt               归一化 + 滑动窗口 + LCS / 字符重叠
├── Prefs.kt                     参数读写（每轮循环重新读取，改动即时生效）
├── AppState.kt                  检测端 → 界面的单向数据流
└── ui/Theme.kt                  Material 3 明暗主题
```

几个实现上的细节：

- **节点匹配放在系统侧**。用 `findAccessibilityNodeInfosByText` 而不是自己遍历，一次 IPC 拿到结果，不搬运整棵树。
- **截图的预筛**。全屏视频页顶部是亮的，画中画广告顶部是纯黑的。把顶部 10% 缩到 16×8 算个平均亮度，不到 1ms，能挡掉绝大多数不必要的 OCR。
- **OCR 只跑底部一条**，缩到 480px 宽，比整屏识别便宜一个数量级。
- **在本 App 界面内不检测**，避免把自己的说明文字当成触发源。
- **手势起点横向随机偏移**，避免每次都是同一条完美竖线。

## 六、编译

```bash
# 需要 JDK 17（AGP 8.x 的硬性要求）
./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

也可以直接用 Android Studio 打开本目录。

- `gradle/wrapper/gradle-wrapper.properties` 的 distributionUrl 指向腾讯云镜像，国内下载快。
- APK 约 30MB，主要是 ML Kit 中文离线模型和 native 库。如果确定只在原生渲染的 App 上用、不需要兜底，可以删掉 `com.google.mlkit:text-recognition-chinese` 依赖和 `StripOcr.kt`，体积降到 2MB 左右。

## 七、已知限制

- 兜底截图依赖 `AccessibilityService.takeScreenshot()`，**API 30 及以上**才有。低版本会退化成纯节点模式。
- 系统级安全界面（支付、密码框）不暴露节点，也不允许截图。
- 少数 App 的提示是画在画面里的，且页面不是画中画形态（顶部不黑），预筛会跳过——这是刻意的取舍，否则正常看剧时也要一直跑 OCR。
- 无障碍服务被系统回收后需要重新开启（后台常驻一般很稳）。
